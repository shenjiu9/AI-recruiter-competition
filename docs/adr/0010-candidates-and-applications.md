# ADR 0010：候选人、简历与应聘记录

状态：已实施比赛版核心流程；外部适配与后续模块边界如下。

## 数据与事务

- `cand.candidate` 保存加密档案；`cand.resume` 分离加密元数据和加密原件；`cand.candidate_identity` 用带密钥的 HMAC 保存历次手机号、邮箱标识。同一人的多份简历复用候选人 ID；联系方式归一化后命中两个不同档案时返回冲突，由 HR 核对。
- 别名保留新旧联系方式，避免“新手机 + 旧邮箱”归档后，再上传仅含新手机的简历重复建档。合并后仍保留原始归属，撤销和删除可追溯处理。
- `appl.application` 独立保存应聘记录。可空唯一键 `canonical_candidate:position` 约束进行中记录，终止后允许重新挂人。共享组织事务锁串行处理身份、权限、合并、挂人和岗位关闭；写入、审计、事件、幂等回执同事务。
- 写接口的幂等回执只缓存对象 ID / 删除标志，不缓存候选人、简历、联系方式等内容；每次响应重新核验权限和读取当前档案。已删除对象不能通过旧请求复活。删除成功后重放会返回 404，客户端应刷新核对删除结果。
- 迁移 `0008` 建档案、简历和应聘表，`0009` 建身份别名表并回填已有联系方式哈希。本地开发库已升级，生产升级使用 `alembic upgrade head`。

## 上传与解析

支持单个不超过 20 MB 的 PDF、DOCX、旧版 DOC、PNG、JPEG。HR 页面可一次选择最多 200 个文件，逐个上传并展示成功、归并、失败结果，失败项保留原幂等键重试。上传流有服务端体积上限，校验文件扩展名和签名；下载需重新鉴权、记录审计，以 attachment / nosniff 返回。

DOCX 读取文本段落，PDF 使用 pypdf 提取文本。解析在独立进程中执行，12 秒超时，DOCX 限制解压总量和文件数量并拒绝实体定义，PDF 最多 50 页；Linux 子进程有 512 MB 地址空间限制。Windows 尚无硬内存上限，生产文档解析应使用独立限额容器。提取以明确标签和联系方式规则为基础，没有伪装为大模型解析；图片、无文本扫描件和旧版 Word 标为待人工补全，坏文件标为解析失败。HR 可核对和修正字段，保留原件。

依据：[pypdf 文本提取说明](https://pypdf.readthedocs.io/en/latest/user/extract-text.html)。文本提取不等于 OCR，压缩页面流可能消耗大量内存，因此保留进程隔离与限额。

当前原件使用数据库加密 BLOB 适配器，保证档案、文件和删除原子一致，便于比赛本地运行；没有声称已接通 S3。对象存储适配、病毒扫描、OCR、ZIP / Excel 模板导入及大文件吞吐验证归入部署与导入增强，尚未验收。

## 隐私与合并

- 结构化资料只接收白名单字段；不接受年龄、性别、婚育、民族、身份证号等字段。解析过滤明确含受保护属性的行，原件仅供获授权 HR 下载，绝不直接作为 AI 输入。
- 当前过滤是确定性规则，不能保证识别所有隐含敏感描述；正式 AI 接入时还需独立输入审查与对抗测试。评估公共入口仅返回授权后的安全结构化资料，排除姓名、联系方式、薪资及原件文本；AI 尚未执行评估。
- 人才库未关联岗位的档案对具备部门范围的正式招聘 HR 可见；有关联时至少有一个可见岗位才可读。业务角色只读岗位关联档案，联系方式始终脱敏，无原件入口和期望薪资。范围外投递仅返回岗位名、时间、结论和定位标识。
- HR 默认也只看脱敏联系方式，点击查看、开始编辑读取原联系方式、下载均留审计。原始简历解析字段和段落在普通响应中脱敏，幂等缓存和通用审计不含明文个人信息。
- 手动导入默认待授权。HR 登记本人授权或撤回须填写证据引用和说明；无授权不能进入 AI 评估。不再联系、撤回授权禁止新挂入；合并及撤销合并不能放宽已记录的隐私选择。
- 姓名、学校、毕业年份相同生成详情页疑似重复提示，由 HR 确认。合并保留全部简历、应聘记录，7 天内可撤销；同岗两个进行中记录必须先终止一个。当前主档案字段优先，HR 可核对后修正，**未实现 PRD 的最新简历自动覆盖冲突字段**。目标已有合并时需先撤销，避免嵌套撤销歧义。
- 删除请求物理移除整个合并组的档案、原件、别名和应聘记录，只保留不含个人信息的审计 / 事件 ID。未来会话、搜索、外部对象存储和备份中的删除须由对应模块接入，不能把当前删除能力称为跨外部系统删除已完成。

## 应聘与岗位联动

- 候选人页和岗位页读取同一应聘表；两端挂人即时写入，页面每 4 秒更新。岗位人数为真实记录投影；尚无录用模块，因此不能手动伪造已录用人数。
- 仅招聘中的岗位可以新挂人；暂停的继续 / 冻结策略约束在途阶段推进，关闭岗位与所有在途记录终止、编制预占释放同事务。
- 淘汰后按 PRD 寻访口径冷却 182 天，范围为同岗或同序列同职级；HR 强制挂入须填原因，登记主动投递须提供证据。默认不发通知。撤销淘汰、回退、放弃、转岗均有明确权限和原因要求；转岗目标失败会回滚原记录终止。
- 推进只能下一阶段，保留最远阶段及历史；进入 AI 评估须有授权。进入面试只记录阶段事件，实际排期由 B07 消费；当前阻止绕过面试完成直接进入用人部门评估、绕过录用审批进入已录用。
- 淘汰通知发送 / 次工作日撤销窗口由 B06 实现；当前请求发送会明确失败，不假称发送成功。候选人自助签名授权链接、会话和接管由 B06 接入；面评、录用与 AI 评估分别由 B07 / B08 / B09 接入。

## 验证与其余边界

后端覆盖解析、受保护字段、文件错误、身份别名、并发去重 / 挂人 / 关闭、脱敏、越权、授权与隐私合并、冷却、回退、终止 / 撤销、转岗回滚、删除和审计。Playwright 覆盖真实 HR 创建的丢响应重试、两端挂人、授权、冷却强挂、390px 业务 H5 脱敏、简历导入 / 归并 / 下载 / 人工修正、合并撤销、不再联系与删除。

列表现在是权限过滤后的加密记录扫描；比赛规模可运行，尚无生产级搜索投影和性能验收。保留期限只记录到期日期，自动续期 / 匿名化定时任务尚未实现。AI 搜索 / 推荐、异步导出、批量标签 / 批量挂人、完整筛选、原件在线预览及统一疑似重复决策卡仍待相应增强；不能据此宣称整份 PRD 已验收。
