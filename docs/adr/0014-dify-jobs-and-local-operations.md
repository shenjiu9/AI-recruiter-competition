# 0014：Dify 建议、持久化任务与本机运维

日期：2026-11-05（本机时区）；对应迁移 `0013_ai_jobs`。

## 决策与实际范围

模型只返回 JSON 建议。业务权限、证据引用、配置版本、候选人授权、阶段变更由 Python 后端校验；Dify 工作流不持有业务数据库、招聘 API 或消息发送凭据。

`engine.job` 保存加密输入、校验后的输出、模型运行编号、token 数、耗时与状态历史。两条队列分别处理实时回复和批处理。领取任务时短暂持有现有组织事务锁，以候选人作为分区（岗位任务以岗位分区）；模型调用发生在事务外。400 秒租约覆盖三次独立调用，每次超时最多 120 秒；过期可重领，旧 lease 的结果不能覆盖新任务。最多三次尝试，失败后进入 dead，可人工重新排队。网关连续三次故障在当前进程熔断 60 秒；持久化重试仍由数据库负责。

任务在执行前、完成后和人工确认时重查发起人权限版本、候选人授权、原文、岗位／画像／知识版本与三级策略版本。变化后取消旧结果，HR 重新生成。新消息、接管、转人工、撤回授权、不再联系、合并与岗位冻结都会阻止旧上下文继续执行。删除候选人时同事务物理删除关联任务。审计事件只含对象编号和错误码，原文不写事件日志。

| 组件 | 本次可用行为 | 当前边界 |
| --- | --- | --- |
| A1 | 从已有岗位生成画像／JD 草稿，复核后保存编辑版 | 仍须经理确认生效；尚未替代需求页原有对话式起草入口 |
| A2 | 岗位人才搜索关键词建议 | 尚未执行渠道搜索、内部全库排名或自动挂人 |
| A3 | 已授权资料中有逐字证据的职业字段提取，复核后更新 | OCR、对象存储和批量冲突合并未在此实现 |
| A4 | 首条标识 AI 身份；公开知识逐字引用、职业必问项与中性回复 | 当前自动披露仅 proactive；asked／协商等交给 HR；渠道仅候选人 H5 |
| A5 | 必须／加分／风险逐项证据校验，三次采样、确定性结论与把握度 | 引用匹配不证明语义判断一定正确；真实质量门槛尚待样本评测 |
| A6 | 本轮面试官根据授权记录生成有引用的记录整理稿 | 不评分、不提交面评，不等于完整 AI 初面或音视频转写 |
| A7 | 当前授权岗位的聚合数据洞察建议 | 不等于跨岗位自然语言 BI 或录用决定 |

默认关闭 AI worker、组件及自动执行。开启工作流连接后，人工模式可以显式生成并复核；影子模式只留结果且不能执行；正常模式只有 A4 回复与 A5 的 advance 支持 L3，且须达到高阈值。关键候选人、保密岗位、注入嫌疑、敏感内容会降至复核；淘汰须人工确认，录用始终走已有经理决定与审批。其他自动化节点不能因为 UI 设置为 L3 就视为已实现。

自动调度消费 application.stage_changed、candidate.resume_added、candidate.consent，消费回执独立持久化。A4 根据持久化消息等待 10 秒再排队。人工模式不自动调度；关闭或未配置组件时不追补历史任务。候选人自助授权后如没有新的可消费事件，可由 HR 显式发起。任务页提供版本冲突刷新、同键重试、取消、拒绝、重排与原文复核。

## 本机部署

Dify 官方 `1.19.0` 独立部署到项目外 `../dify-local`，使用 Windows 适配的命名卷及仅回环端口。初始化与插件存储均按容器实际 UID 1001 配置权限。DeepSeek 官方插件 `0.0.26` 安装成功，七个 DSL 草稿通过真实 Dify 导入。模型参数使用 `deepseek-flash`、关闭 thinking、JSON 输出、4096 输出 token 上限；模型密钥尚缺，未发布可调用工作流，未声称真实模型成功。

管理员凭据保存在被 Git 忽略的 `backend/.env.dify-local`。Dify 的 `docker/.env` 和生成的 `compose.local.json` 都包含私有配置，不能提交 Git。后者是完整解析后的 Compose，启动时只传 `-f compose.local.json`，不能再与官方主文件合并。

## 运维与验证边界

- `/api/v1/hr/operations` 仅管理员可见，返回队列／消费状态计数、最早到期延迟和配置状态，不含候选人原文。
- 导出 83 条路径的 OpenAPI 快照，并在 CI 检查漂移；前端 TypeScript 契约仍由类型检查和联调验证，尚未替换为全自动生成客户端。
- PostgreSQL 备份使用 `pg_export_snapshot` 保证行数清单与 pg_dump 来自同一快照，备份整体加密；恢复演练只创建随机 `_test` 库，核对表行数、迁移版本和业务 AES-GCM 解密后删除该测试库，不覆盖项目库。
- 已完成真实本机 PostgreSQL 全套 327 项回归及迁移降至 base／再升级／schema 检查；之后增加运行状态、权限变化、证据类型、并发领取、事务回滚和其他组件契约测试，专项结果记录在交付计划中。
- 29 项浏览器全套通过；AI 边界使用仅位于临时测试服务器中的确定性 fixture。HTTP 网关另有真实本地 HTTP 服务测试，覆盖请求协议、重定向拒绝和熔断。这些不是 DeepSeek 质量评测。
- 本机六并发、120 次只读请求、演示数据：无错误，P95 115.5 ms。没有大数据量／生产 SLA／持续压力或故障切换的验收结论。
