# ADR 0012：面试预约、排期与本人面评

状态：B07 比赛版内部闭环已实现，真实会议 / 日历适配器尚未接通。

## 已实现的行为

- 应聘进入面试阶段时创建首轮面试，快照岗位面试流程和必问题。岗位后续修改不覆盖在途流程；缺少流程时明确显示待配置。通过后自动生成下一轮，末轮通过进入业务评估，不直接录用。撤销淘汰或从业务评估回退到面试时建立新的面试周期，旧记录继续保留。
- HR 可生成最多四个跨日可选时段，搜索未来七个工作日，提前至少 26 小时，软占位 24 小时；不足四个时返回实际可用数量，无共同时间返回协调提示。工作日 / 节假日 / 调休使用已有配置。业务端可维护可面星期、北京时间起止小时、每日 / 每周上限及前后缓冲。
- 预约同时占用候选人和全部面试官，跨岗位检查冲突。候选人身份按主档案归一；已约 / 约面中 / 待面评期间禁止合并或拆分身份。确认预约会同事务释放其余备选时段并建立正式预约；过期占位由后台或下次预约清理。
- 候选人沿用 B06 签名链接，只有本人可预约；看不到内部评分、结论和薪资。HR 可手动填写时间，现场面试要求地址，未配置会议服务的视频面试要求已核实的 HTTPS 链接。安排前由 HR 明确确认已核实外部日历。
- 距开始至少两小时且前两次候选人改期，释放旧时段后由 HR 提供新时段；第三次、临近开始及面试官申请改期，保留原预约等待 HR 协调。取消、应聘终止和岗位关闭释放占位；授权撤回或不再联系释放未确认备选时间，阻止新预约，已确认场次由 HR 协调。
- 没有真实参会数据，因此实际结束和开始后十五分钟的缺席均由 HR 核实确认。岗位冻结阻止新安排和面评结果推进。
- 面评由指定且当前仍具备角色 / 部门范围的面试官本人填写。各维度严格为整数 1–5，结论手动选择，必问题须回答，待定 / 不推荐须填写顾虑，须核实并声明无回避情形。没有 AI 预填或代签。
- 本轮提交前隐藏他人及前轮的详细评分与理由。首次提交后 24 小时内可修订并保存加密历史，之后只能追加备注；已用于后轮正式安排的结论不能直接改写。全部面评齐备后按一致 / 多数 / 指定人规则计算；非通过进入待 HR 决策，不自动淘汰。
- HR 面试列表、候选人和岗位入口、岗位实际面试安排、业务 H5 我的面试 / 面试准备 / 面评、候选人 H5 预约 / 改期已接入真实 API。写入丢响应后保留原载荷和幂等键重试；版本冲突保留输入，要求刷新核对。

## 事务与运行

迁移 `0011` 新增 `iv.interview`、`iv.reservation` 和 `iv.availability`。面试详情、面评、操作原因和偏好加密保存；预约资源键与时间用于数据库冲突检查。PostgreSQL 使用 `btree_gist` 和半开时间范围排他约束，迁移账号须可创建该扩展。SQLite 用于本地开发，不能替代 PostgreSQL 原生并发验收。

比赛规模下复用组织配置事务锁，预约、版本 CAS、应聘阶段、审计 / 事件与幂等回执同事务。幂等回执仅保存 ID，重试重新核验身份并构造当前视图。面试状态通过五秒轮询刷新。`CONVERSATION_WORKER_ENABLED` 控制的现有后台循环同时执行面试占位过期、提醒记录和外部同步步骤；单次任务函数为 `app.interview_worker.run_once(container)`。

提醒仅保存站内记录：候选人前一天 18 点 / 提前一小时、面试官提前十五分钟，以及结束后 2 / 24 / 48 小时缺失面评。改期清除上一安排的提醒去重标记；重启读取持久化状态。没有发送飞书、邮件、短信或推送。

## 外部集成的准确边界

目前默认 `interview_gateway = None`，使用人工核实模式。新增的是会议 / 日历端口和持久化创建、清理、重试状态机，**没有生产可用的腾讯会议 / 飞书 SDK 适配器、凭证配置或真实调用验收**。

可注入端口先创建会议，再创建日历，每步提交引用。确定拒绝时补偿清理已知资源；超时 / 丢响应重试原幂等键，连续失败显示结果待核实，禁止当作未创建直接取消。再次重试继续使用原键，取得引用后才可清理。异常文本不入库。录制始终关闭，勾选同意不等于开启录制。

生产适配器必须提供有界超时、按键查回原资源和可重放的取消。当前外部端口调用仍处在全局事务锁内，正式接入前应迁移为 B09 任务队列并处理调用成功但数据库提交失败的恢复；本次测试不能代替真实服务故障演练。
