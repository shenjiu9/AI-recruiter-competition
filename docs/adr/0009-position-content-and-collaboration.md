# ADR 0009：岗位内容版本、发布审批与协作

状态：已实现，验收结果见交付计划最新记录。依据 PRD 7.6、8.3、8.4、15.1 与详细设计 position 门面。本次按岗位管理统一交付，不再新增字母子批次；跨候选人、渠道、录用和 AI 的依赖按对应模块验收。

## 画像与 JD

画像分为最新编辑版和当前生效版。发布前和招聘中均可编辑必备条件、逐行加分项及高 / 中 / 低权重、不合适信号和必问项。每次保存生成新版本；经理确认前旧版继续生效，确认采用岗位版本 CAS，防止确认过时内容。`current_profile` 仅返回生效画像和稳定条目引用，不含内部薪资。历史保存在加密岗位载荷中，旧数据可从已有确认 / 编辑记录恢复版本。

JD 有独立草稿、批准状态、生效版本和历史。招聘负责人配置本岗位是否需要 JD 审批；开启时须由具有本部门范围的另一位招聘负责人审批，作者不可自审。编辑清除本版本审批，旧生效 JD 不变；发布或“启用新版 JD”再次核验当前版本审批人角色和范围。画像与 JD 在保存 / 确认 / 发布时做现有基础歧视词检查，这不代表完整的可配置红线词库已经实现。

岗位详情可查看画像和 JD 历史并逐版对照。发布前未确认或 JD 待审批时按钮不可用，后端仍独立校验。经理可在业务 H5 查看岗位列表、画像与历史、知识条目和协作留言，确认画像与关闭请求，并补充知识库；“修改并确认”在同一事务生成新画像版本并确认，保留旧版本。飞书 IM 卡片仍待外部集成。

## 知识披露

岗位知识条目包含内容、来源、披露级别、版本、创建者和时间，默认仅内部参考。支持“可主动说 / 被问到可说 / 仅内部参考 / 转人工”。修订生成新 ID 并立即使旧 ID 失效，下线保留历史；写操作发布 `kb.changed`，事件载荷仅包含岗位 ID 和版本，正文不进入通用审计或事件。

`knowledge_for_reply` 先校验岗位范围，再按场景过滤：主动只含 proactive，被问到可含 asked；internal、handoff 不输出正文，保密岗位不返回任何可披露知识。无依据或存在转人工条目时提示人工确认。指定旧 ID、其他岗位 ID、下线 ID 或不符合当前披露场景的引用会被拒绝。前端提供对外答复预览，便于维护者核对。

此处是知识维护和引用校验能力，不会发送消息或调用 Dify。公司通用知识、知识检索相关性、待补充问题频次、Dify 同步和候选人实际对话中的引用校验在设置 / 沟通 / AI 模块接入，不能将预览视为 AI 已完成对外答疑。

## 协作、关闭与面试配置

负责 HR 或招聘负责人可增删最多 5 位共享 HR，在职、招聘角色和部门范围均校验；共享 HR 可编辑内容，但不能自行扩展共享或转交负责人。留言支持明确选择本岗位成员作为提及对象，当前仅站内保存，不投递飞书消息。

迁移 `0007` 在需求模块增加独立 `position_source_access` 读权限表。岗位通过需求公开门面同步负责人和共享成员，岗位变更与来源权限同事务；不改写原申请人、审批人或保密名单。撤销共享 / 转交后撤销该项额外权限；原始参与者仍保留其原有可见权。新增共享成员失去部门范围后不能继续读岗位或来源需求。岗位写接口在读取幂等缓存前重新加锁鉴权，防止撤权后重放旧响应。

普通负责 / 共享 HR 可申请关闭，经理确认前状态和编制预占不变；经理可确认或填写原因驳回，禁止申请人自确认。招聘负责人仍可直接关闭。关闭状态、原年度正式预占释放、审计、事件和幂等响应同事务；确认和驳回竞争只有一个成功。

面试流程支持 1–6 轮、顺序、名称、形式、时长、在职面试官、通过规则及评价项；指定决定人须在本轮面试官中。每次保存完整新版本，旧版保持不变。这里只维护配置；面试官组 / 轮询、模板、候选人实际绑定旧流程、重评建议、排期和面评由后续面试 / 候选人模块接入。

## 同岗选择超时

生成选择保存 3 个工作日截止时间，由现有持久化岗位订阅器定期检查，到期仍未处理则新建独立岗位。与手工合并共享事务锁和版本约束，不能重复生成或重复累计人数；重启后根据数据库继续处理。

按 Asia/Shanghai 的日期和原时间计算，周末默认休息；部署方配置 `POSITION_HOLIDAYS` 与 `POSITION_WORKDAYS` 两个 JSON 日期数组覆盖节假日和调休。示例仅为格式：`["2026-11-09"]`，不是预置官方节假日日历。新任务保存当时的截止时间，修改配置不会回溯改变已有任务。旧任务未保存截止时间时按当前配置计算。尚未接入通用工作台决策卡。
