# ADR 0002：终审编制原子预占

## 决策

正式需求最后一个审批节点通过前，通过 org 公共门面预占本年度编制。以数据库条件 UPDATE 同时检查生效日期、未冻结和 `planned - used - reserved >= count`，成功后增加预占人数与版本，写入以需求 ID 唯一的预占记录。需求 CAS 更新、预占、审计、审批事件和幂等响应使用同一个事务。该强一致约束不能交给异步事件补扣；请求模块不访问 org 私有表。

预占不足时保留审批中，追加终审编制复核节点。负责人必须先维护实际额度，再审批；点击通过或填写增编申请不会凭空增加额度。异常节点的负责人在提交时拍快照，之后组织策略变化不会静默改变当前审批对象。旧版审批中需求没有此快照时，提示撤回重提，不猜测负责人。冻结与缺少生效计划也不能绕过。

相同需求重复终审由需求版本冲突回滚多余预占。SQLAlchemy 在执行需求 CAS 之前禁止 autoflush，避免先 flush 预占唯一键导致 500；需求 CAS 成功后才 flush 预占与审计。PostgreSQL 测试使用 barrier 确保两个终审同时到达预占入口，验证竞争名额与同一需求竞争两条路径。

## 配置与权限

年度编制支持单条新增、维护、冻结、生效日期与版本校验，仅允许授权部门内的 HRBP / 编制负责人。预占数只由业务事务更新，接口拒绝手工写入。修改不能使计划低于已用加预占。维护前后完整编制快照存入不可变审计；自动预占不刷新人工维护日期，超过 30 天仍提示过期。

迁移 `0002` 不从旧演示 policy 推断真实预算。没有预算时阻止正式需求提交，开发种子显式提供演示额度。既有已通过需求不会追溯补扣；有存量业务的环境必须先对账、将存量占用计入额度基线，再开放新需求。当前仓库仅有开发演示数据。

## 当前边界

本批只支持部门 × 自然年度，终审前的待审批需求不扣额度；页面明确展示“招聘预占”。季度编制、待审批人数投影、年度结转、Excel 导入、历史版本浏览尚未交付。岗位关闭释放、入职后从预占转已用在岗位/录用批次实现；在此之前不提供批准后撤销或人工改写预占的接口。

薪资仍使用上一批部门级演示上限，序列 × 职级 × 城市薪资表和独立 HRD 加签是下一任务；本批不宣称整个 B03 或完整 PRD 已实现。
