# 测试反馈与岗位简历匹配

## 反馈核验

2026-11-07 核验飞书《AI招聘官测试文档》的 5 条有效反馈。

| 反馈 | 核验结果 | 调整 |
| --- | --- | --- |
| 汇报对象不能多选、搜索与选择分离 | 汇报对象按业务规则为单人；交互不直观 | 搜索与下拉合并，明确单选；保密可见人员支持搜索多选及移除 |
| 职级薪资应关联配置表 | 建议成立，原表单主要手填 | 读取当前生效配置，一次带入序列、职级、城市、薪资，仍可修改；维护权限保持独立 |
| 预检信息远离输入项 | 问题存在 | 对应字段显示颜色、原因及悬浮说明，侧栏可定位修改 |
| 不理解终审编制复核 | 状态正常，解释不足 | 明确增编申请不自动增加年度名额，提示编制负责人核对计划、占用、生效及冻结状态 |
| 工作台待审批为零；审批人能撤回 | 两处均为真实缺陷 | 汇总当前轮到本人的招聘需求审批及录用审批；只有需求当前负责人可撤回，审批人用驳回 |

业务端工作台的招聘需求链接打开该端的需求审批弹窗；HR 端打开需求详情。权限仍由服务端核验。

## AI 匹配的变化

此前 A2 只生成寻访关键词；A5 已调用模型，但只针对已进入「AI 评估」阶段的单条应聘记录。因此此前没有从人才库挑选简历、按岗位逐项比较的完整入口。

现在 A2 从后端取得岗位生效画像，以及当前 HR 有权查看、已授权且未停止处理的候选人资料。HR 可选择最多 5 人；未选择时使用最近创建的最多 5 位可用候选人。这是有限批次比较，不是全库检索召回。

后端脱敏并将每人资料限制为最多 6000 字、24 段、单段 1500 字，再交给 Dify / DeepSeek。模型必须覆盖岗位条目并引用各人自己的原文；缺失、错误引用或借用另一人证据不能作为符合依据。服务端计算参考分、证据覆盖率和待补充项，页面显示姓名、条目与原文链接。参考分沿用 A5 的必备项 60 分、加分项 40 分及风险扣分规则，不代表录用概率。

A2 复核只记录已阅建议，不自动关联岗位、淘汰或录用。HR 查看资料后手动关联，再进入沟通及 A5 证据评估。查询、运行结束与复核时重新检查权限、授权和资料版本；删除候选人会删除包含其资料的整批匹配任务。

公网真实模型验收曾出现“引用 Excel 经历，推断不具备 Python 能力”的错误负面推断。引用存在不等于推论成立，因此 A2 的所有 `not_meet` 均由后端降为 `unknown`，显示模型提示并要求人工核实，不据此输出拒绝结论。A5 的独立证据评估与人工确认流程保持原有规则。

## 更新与验证方式

新增表单只读接口 `/api/v1/hr/requisition-form/salary-options`，以及 A2 启动参数 `candidate_ids`。不涉及数据库迁移。旧客户端可不传此参数；旧 A2 任务可能因输入契约变化失效，重新发起即可。

仅更新 A0 路由说明与 A2 匹配工作流：

```bash
python deploy/provision_dify_local.py --components A0 A2 --sync-drafts --publish
```

工具会将原 DSL 备份至被 Git 忽略的 `backups/dify-workflows`，保留其他组件密钥和云端地址，并关闭匿名 WebApp。

`test_feedback_matching.py` 覆盖审批计数、撤回权限、薪资目录范围、匹配证据隔离、撤回授权及删除资料。`test_recruiting_closed_loop.py` 让一份合成 DOCX 从审批、发布、提取、匹配、沟通、评估、预约及面评一直走到录用、移交、入职；仅隔离测试时钟跳过面试等待。

默认自动化测试使用确定性模型边界。显式设置 `LIVE_DIFY_ENV` 为本机私密环境文件路径，可在隔离测试库中运行真实 Dify 的 A3、A2 和三次 A5 调用。该模式产生模型费用，不写线上招聘数据。独立 `smoke_dify.py` 验证 A1–A7 真实模型输出，其中 A2 包含符合与证据不足两份合成资料。

飞书、腾讯会议、短信、邮件及招聘渠道仍待外部应用配置；未将这些集成的模拟测试视为真实服务联调。
