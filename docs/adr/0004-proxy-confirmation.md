# ADR 0004：代发起需求修改确认与字段差异

## 确认与权限

代发起需求始终由原创建人决定代理身份：即使归属经理提交 HR 保存的草稿，首节点仍是用人经理确认。`POST /api/v1/hr/requisitions/{id}/confirmation-preview` 只读预检，`POST /{id}/confirm` 使用 `expected_version`、`fields` 和幂等键原子完成修改与确认。原 `/approve` 的 manager 节点委托同一确认逻辑，支持直接确认原内容。

只有审批中、首节点为 manager 的当前经理可以修改确认。可改岗位内容、人数、用工/招聘类型、职级薪资和增编申请；部门、负责 HR、保密范围及未实现的自定义字段不允许通过此接口变更，须撤回后由有权限的人修改。后续审批人没有编辑权。人事目录、替补与追加关系尚未接入，预检沿用已有阻断。

HR Web 详情与业务 H5 待办提供“修改并确认”，展示预检、字段前后值和后续审批链。未修改时可直接确认；修改后必须通过预检。预览不缓存幂等响应，正式确认再次校验，预览通过不等于预留编制。

## 规则快照

提交时将部门审批策略、薪资判定与版本引用保存到需求的加密载荷。确认时原有审批人保持提交快照；增编条件变化可以增删 `hc` 节点，薪资条件变化可以增删 `salary` 节点，新加节点的负责人仍来自提交时策略。缺失有效 HRD、HRD 为创建人或归属经理均阻止确认，不使用后来修改的组织配置替换审批人。

薪资、序列、职级或城市变化属于新的报价，使用确认时生效的薪资表重新判断，并记录新版本引用。只修改其他字段保留提交时薪资判定；薪资配置更新本身不会改变在途审批。HC 校验使用当前可用额度，正式需求的最终预占仍在最后一个审批节点原子完成。

无修改确认保留原提交结果，不因日期推移或配置更新重新阻断；最终 HC 复核仍执行。旧版载荷无规则快照时可原样确认，但修改必须撤回重提，以建立完整快照。此次仅扩展加密 JSON，未改数据库表，不需要新迁移。

## 差异、事务与重试

确认保存一条 `manager_confirmed` 记录，含操作者、时间、字段 before/after、确认后的审批链和薪资版本引用。重新提交保存与上次提交字段快照的差异；首次提交和旧版无基线的第一次重提不伪造差异。两端可查看经理确认差异，HR 处理记录可查看重提差异。

字段与详细差异仅在加密需求载荷/加密幂等响应中保存，沿用需求读取权限。通用审计和事件只有状态、版本、对象标识，不写入薪资或自由文本。字段修改、审批推进、访问索引、审计、事件和幂等响应处于同一事务；CAS 失败时全部回滚。预览无写入。

编辑期间固定原始版本，刷新不能默默把旧输入提交到新版本。409 保留输入并阻止继续提交，提示关闭后刷新核对；网络错误或 5xx 锁定当前输入，重试使用原请求体和原幂等键，避免响应丢失造成重复确认。

## 验证与后续

专项测试覆盖权限、身份/范围字段锁定、预检阻断、HC/HRD 条件增删、审批人快照、薪资版本、加密差异、失败回滚、旧载荷兼容、重复确认、确认与撤回并发、经理提交代理草稿以及重提差异。PostgreSQL 并发测试在两个事务保存前使用 barrier 强制交错。浏览器覆盖两端修改确认、差异展示、后续完整审批、过期版本与丢响应重试。

正式身份/组织目录、角色范围和审批人配置、离职转交、差异专用对比视图、自定义字段及细分薪资可见权限属于后续 B03 子任务。此批不引入 Agent 框架，也不消费审批事件生成岗位。
