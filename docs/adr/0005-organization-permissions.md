# ADR 0005：组织目录、角色范围与审批人配置

## 目录边界

按 PRD 14.3，组织、姓名、在职状态、汇报关系和用人经理属于通讯录来源，本批不提供修改这些数据的 HTTP 接口。新增 `/settings/organization` 展示已导入目录，维护本系统的角色与部门授权、招聘需求审批人配置。该页面不代表飞书 SSO、事件同步或每日对账已经实现。

`org.user.roles/departments` 保存人工授权，`directory_roles/directory_departments` 保存目录派生角色和部门；实际角色、范围取并集。迁移 `0004` 将旧的 hiring_manager 角色及其范围移入目录字段，避免人工撤权误删目录关系，也避免后续目录移除角色后旧授权残留。回退前合并两个来源，保留旧版本所需角色和范围。迁移不创建生产管理员、不推断部门上下级；已有部门的 `parent_id` 初始为空。

目录端口提供用户、部门策略和范围展开。范围按 `parent_id` 的真实关联包含下级，不能依赖部门名字前缀。正式目录适配器后续必须校验唯一 ID、有效上级及无环关系，在同一事务更新来源字段，并为有效权限变化的人员递增权限版本；不得覆盖人工角色授权。当前没有远程目录写入接口、飞书凭据或同步调度。

## 管理权限与业务隔离

- `admin` 可查看全量目录、修改权限与审批人、查看历史。招聘负责人只读授权部门的配置；人员列表过滤到相关人员，部门授权信息裁剪到查看人的范围。人员权限历史仅管理员可读。
- 人工可授予招聘负责人、招聘 HR、HRBP、编制负责人、HRD、薪酬负责人、面试官和管理员。用人经理派生角色、姓名、在职状态、来源部门不接受 API 修改；未知角色、未知部门、离职人员授权均拒绝。
- 单独的管理员角色不能查看或发起招聘业务，不能读取薪资表；多角色遵循权限并集。普通招聘 HR 的需求读取收紧为创建 / 审批 / 明确共享关系，招聘负责人、用人经理及 HRBP 可读范围内非保密需求。岗位负责与共享关系待 B04 建立后接入。
- JWT 每次请求重新读取当前角色和范围。当前审批人在签字时还必须拥有对应角色和部门范围，撤权后不会因在审批快照中就继续获准签字；在途审批人身份保持快照，自动转交尚待下一批。
- 写请求指纹包含当前权限版本，权限改变后旧幂等键返回冲突，既不泄露旧缓存响应，也不产生一笔新的重复业务写入。升级前的旧指纹也会冲突，客户端应刷新核对结果。前端菜单使用登录时角色；权限变化后重新登录可刷新菜单，服务端校验即时生效。

## 并发与版本历史

授权和审批配置各有版本，写入必须携带 expected_version 和幂等键。组织配置写操作先取得数据库单行事务锁，再重新读取操作者授权；防止等待锁的旧管理员请求在被撤权后仍生效。最后一名在职管理员不能被移除，两个管理员并发互相撤权或撤销自身权限也不能清空管理员集合。

第一次修改保存初始快照，随后每次修改追加版本和操作人、时间，并记录通用审计。初始快照时间是首次记录时间，操作人显示“初始快照”，不伪造历史发布时间。数据库写入、版本、历史、审计和幂等响应同事务，失败一起回滚。恢复历史版本通过“以此版本编辑”发布新版本，重新校验当前在职状态、角色和范围，不改写旧历史。

新增的 `org.configuration_revision` 保存组织配置，不包含招聘字段或薪资数值；组织接口过滤掉旧策略中的 available_hc / salary_max，真实编制、薪资仍由各自模块维护。本批只读目录采用服务端分页响应和搜索，未来大规模通讯录需要进一步将筛选和层级查询下推数据库。

## 审批配置与试算

当前固定流程为经理确认（代理发起时）→ 部门负责人 → HRBP → 条件 HC / HRD 加签。管理员可维护部门负责人、HRBP、编制负责人和 HRD；经理来自目录。每个目标须在职、具有对应角色及部门范围，后续审批人与归属经理必须独立；创建人自审沿用已有上推 / 拦截规则。

“试算”选择有该部门发起权限的人员及增编 / 超带宽条件，返回已发布版本的审批链，不创建需求、不替代真实提交预检。新配置只影响新提交或重新提交的需求，在途需求继续用原快照；代理改动条件时仍按原负责人快照加签。

会签 / 或签、任意节点编排、跳过规则、离职自动转交、HR 细分类型薪资脱敏、HR 分配规则和自动化策略版本尚未交付，不能将此批描述为全部 ST-02 / ST-03 完成。

## 首位管理员与部署

开发种子增加 `admin` 账号，仅在显式开发模式创建。真实部署先完成目录导入，再由持有数据库部署权限的操作人执行：

```powershell
# backend 目录，user-id 必须是已经导入的真实在职用户
.venv\Scripts\python.exe -m app.bootstrap_admin --user-id <用户ID> --expected-version <当前版本>
```

此命令没有 HTTP 路由，仅在没有任何在职管理员时可用，事务内加锁、检查版本并留审计。已有管理员时必须通过正常授权流程，不能用命令绕过已有管理权限。
